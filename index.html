For new operators

처음 쓰는 사람을 위한
LMS 운영 핵심만

메뉴가 많아서 전부 외울 필요는 없습니다. 아래 10개 섹션만 익히면 일상 운영의 80%를 처리할 수 있습니다. 세부 기능은 어드민 안의 Daybear 헬프에서 “어떻게 해요?”로 검색하세요.

대상: 신규 운영진 범위: 핵심만 (고도화 예정) 어드민 진입: /admin/

1. 시작하기 (5분)

접속 → 권한 확인 → 홈 위치만 잡으면 됩니다.

  1. 본인 계정으로 LMS 로그인 후 /admin/ 또는 /admin/dashboard/로 이동합니다.
  2. 어드민이 안 열리면 is_staff 권한이 없는 것입니다. 시니어 운영진/슈퍼유저에게 스태프 권한 부여를 요청하세요.
  3. 공용 계정 대신 개인 계정 사용을 권장합니다. (누가 무엇을 바꿨는지 추적 가능)
  4. 공용 계정을 쓰는 경우 Slack 6자리 2차 인증이 뜰 수 있습니다. 지정된 슬랙 채널의 번호를 확인하세요.
  5. 화면 어딘가의 Daybear(도움말)에서 “출석”, “행사”, “상벌점”처럼 검색해 보세요. 이게 공식 플레이북입니다.
첫날 목표: 운영 홈(/admin/dashboard/)을 열고, 왼쪽 허브 이름만 훑어본 뒤 Daybear로 “출석 CSV”를 한 번 검색해 보기.

2. 메뉴 지도 (어디 가면 되나)

왼쪽은 허브입니다. 자주 쓰는 것만 기억하세요.

운영 홈 / 대시보드·지표

전체 현황을 보는 출발점. 막히면 여기로 돌아오세요.

/admin/dashboard/
일상 운영

매일 쓰는 도구: 출석·상벌점 CSV, B포인트, 심사/승인 대기열.

정규반

분반, 수강, 출결, 과제, 조별활동, 블로그 챌린지.

커뮤니티

공지 작성, 행사 신청 승인, 행사 대시보드.

회원·권한

회원 승인, 유형 변경, 스태프/강사 관련.

BDAI 학회원 모집

모집 시즌에만. 서베이·입금·분반찾기.

Knock / 광고 / 캠퍼스맵 / 기업분석 / HR / 비용 등은 담당 팀이 있을 때 들어가면 됩니다. 신규 운영진 필수 범위는 아닙니다.

3. 주간 루틴 (정규반 운영의 뼈대)

수업이 있는 주에는 이 순서만 지키면 크게 흔들리지 않습니다.

  • 수업 전: 분반 Zoom/자료/과제 공지 상태 확인
  • 수업 후: 출석 반영 (Zoom 또는 CSV)
  • 출결 사유폼 검토 (결석/지각 사유)
  • 필요 시 상벌점 반영
  • 과제 제출률 점검 → 미제출 독려
  • /admin/regulars/dashboard/에서 분반 현황 한 번 훑기
세부 화면 경로는 아래 5·9번을 보세요. “매주 무엇을 할지”만 먼저 몸에 익히면 됩니다.

4. 회원 승인 · 수강 배정

사람이 LMS에 들어오고, 분반에 들어가게 만드는 일.

회원 승인

  1. /admin/accounts/user/에서 승인 대기 회원을 찾습니다.
  2. 회원 상태(승인)와 회원 유형(정규반/일반 등)을 맞춥니다.
  3. 운영진이 될 사람에게만 스태프 권한을 부여합니다. 남발하지 마세요.

수강(Enrollment) CSV

  1. 「일상 운영」또는 「정규반」→ 정규반 CSV 업로드.
  2. 기수/분반/회원 식별값이 어드민 설정과 같은지 확인 후 업로드.
  3. 업로드 결과 메시지를 읽고, 분반·수강 목록에서 인원 수를 검수합니다.
대량 업로드 전에는 소수 행으로 테스트하세요. 중복 시 스킵/갱신 규칙이 달라질 수 있습니다.

5. 출결 · 상벌점 · B포인트

가장 자주 만지는 영역입니다.

출석 반영

  1. 일괄: 「일상 운영」→ 출석 CSV 업로드 (/admin/regulars/attendancerecord/import-csv/)
  2. 분반별 Zoom: 분반 상세의 Zoom 출석 가져오기
  3. 반영 후 「출석 기록」에서 분반·날짜 건수를 검수
  4. 사유폼 제출은 「출결 사유」메뉴에서 검토
FORM/MANUAL로 넣은 출석은 Zoom 재업로드에 덮어쓰지 않도록 보호되는 경우가 많습니다. 숫자가 이상하면 “어떤 경로로 넣었는지”부터 확인하세요. 벌점 자동정리는 보통 주기적으로 돕니다.

상벌점

  1. 「일상 운영」→ 상벌점 CSV 업로드
  2. 회원 식별키(이메일 등)가 계정과 일치하는지 확인
  3. 「상벌점 기록」에서 결과 검수 · 이상치만 개별 수정

B포인트

  1. 「일상 운영」→ B 포인트 지급
  2. 단건 지급 또는 샘플 CSV로 일괄 지급
  3. 사유는 문의 대응용으로 구체적으로 남기기

6. 공지 · 행사 신청

공지 올리고 → 신청 받고 → 승인/안내하는 흐름.

  1. 「커뮤니티」→ 공지에서 글을 작성합니다. 행사이면 신청 기간·정원·Zoom 등을 설정합니다.
  2. 신청 건은 행사 신청 목록에서 승인 / 대기 / 취소를 처리합니다.
  3. 현황은 /admin/notices/event-applications/dashboard/에서 모아서 봅니다.
  4. 필요 시 Zoom 안내 메일·채팅 초대 메일 등 일괄 발송 기능을 사용합니다.
“몇 명 신청했지?”는 개별 목록보다 행사 신청 대시보드가 빠릅니다.

7. 「일상 운영」대기열

매일 한 번씩 열어볼 승인 큐입니다. 담당이 정해져 있으면 그 사람 기준으로 처리하세요.

큐하는 일
강의·클래스 심사 등록된 강의/클래스 콘텐츠 승인·반려
WAVE·원데이·JOB 심사 단편 콘텐츠 심사
강의 VOD 입금 승인 유료 강의 입금 확인 후 접근 허용
자소서·포트폴리오 첨삭 정규반 첨삭 요청 승인/반려
후기 쿠폰 입금 등 프로모션성 입금/요청 처리 (메뉴에 보이면)
확실하지 않은 승인/반려를 임의로 처리하지 마세요. 담당 팀 채널에 먼저 확인하는 게 안전합니다.

8. 시즌 업무 (필요할 때만)

평소엔 닫아두고, 시즌이 열리면 깊게 들어가면 됩니다.

조별활동

활동 생성 → 정보 제출 → 팀 매칭 → 일지/채점 → 중도이탈 모니터링.

정규반 → 조별활동
블로그 챌린지

주차별 주제 등록 → 제출 확인 → 스탬프(승인) 지급.

정규반 → 블로그 챌린지
학회원 모집

모집 페이지/서베이 → 신청서 → 입금 CSV → 미매칭 큐 → 분반찾기.

BDAI 학회원 모집 허브
BDAI Form

구글폼 대신 쓰는 내부 폼. 공개 링크 복사 → 응답 승인 → 대시보드.

/admin/bdai_forms/
조별활동·블로그는 이미 상세 내부 문서가 있습니다. 이 메뉴얼은 “존재와 진입점”만 잡고, 시즌 오픈 시 상세 런북을 링크해 고도화할 예정입니다.

10. 막힐 때

혼자 메뉴를 전부 뒤지지 마세요.

  1. 어드민 Daybear에서 키워드로 검색 (출석, 상벌점, 모집, 첨삭…)
  2. 이 메뉴얼 상단 검색창으로 관련 섹션을 찾기
  3. 그래도 불확실하면 담당 시니어에게 화면 URL + 하려는 일 + 에러/결과 메시지를 붙여 질문
좋은 질문 예시: “출석 CSV 올렸는데 12건 중 2건 실패. URL은 …/import-csv/ 이고 메시지는 ‘회원 없음’입니다. 이메일 매칭 기준이 뭔가요?”

아직 이 메뉴얼에 없는 것

광고·BDAIB, Knock 세부 운영, 캠퍼스맵, 기업분석, HR/비용, NEWTEAMZ/MOU, 배포/서버. 필요해지면 역할별 부록으로 추가할 예정입니다.
